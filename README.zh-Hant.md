# SingLink 3.0 協議（SL3）

SL3 是 SingLinkLabs 的開源代理／VPN 協議。它保留 VLESS、Trojan 快的地方：TLS 連線一開始只送一次請求，第一段資料跟請求一起送出，不多等一個來回。在這個基礎上，它補上正式營運 VPN 服務需要的能力。

## 跟 VLESS 比，多了什麼

| | VLESS | SingLink 3.0 |
|---|---|---|
| 誰能連線 | 拿到共用 UUID 就能連 | 必須持有帳號後台簽發的**權限憑證**，而且要有綁定的裝置金鑰 |
| 節點上的用戶權限 | 協議本身沒有（要靠面板） | 到期時間、TCP／UDP 權限、限速、同時連線數、吊銷，**每個節點離線就能驗證並執行**，節點上不放用戶資料庫 |
| 憑證外洩 | UUID 外洩就能被盜用 | 憑證綁定裝置金鑰，每次連線都要證明持有，從節點偷走憑證也用不了 |
| 傳輸加密 | 只靠外層 TLS（經過 CDN 時，CDN 看得到明文） | 另有一層端到端加密（AES-256-GCM），經過 CDN 也看不到內容 |
| 抗量子 | 沒有 | X25519 + ML-KEM-768（NIST FIPS 203）混合金鑰交換 |
| 前向保密 | 只靠外層 TLS | 內層也有臨時金鑰前向保密 |
| 防主動探測 | 要另外設定回落 | 內建：沒通過驗證的連線，原封不動轉給真實網站；明文探測立即轉交 |
| 防重放 | 沒有 | 時間窗口 + 臨時金鑰快取 |
| 流量特徵 | 可選 Vision | 請求和前幾個資料框都隨機填充長度 |

## 狀態

**版本 3.0.0-draft（草案）。**

- 只用 Go 標準庫的成熟加密元件，不用任何第三方套件，也沒有自創加密演算法。
- 測試已全部通過：協議核心的單元與端對端測試（含競態檢查），以及 Flutter 客戶端的 17 項測試，其中一項連真實核心實測。
- **尚未經過獨立安全審計。** 開源正式發布、或用在高風險用途之前，建議先請第三方做密碼學審計。

## 目錄

| 路徑 | 內容 |
|---|---|
| `SPEC.md` | 協議規格（英文，對外開源用） |
| `core/sl3` | 協議核心（Go） |
| `core/socks5` | 本機 SOCKS5 入口（含 UDP） |
| `core/cmd/sl3` | 命令列工具：產生金鑰、簽發憑證、產生連結、跑節點、跑客戶端、一鍵本機示範 |
| `core/ffi` | 給 App 用的 C 介面 `libsl3` |
| `app/` | Flutter 客戶端殼（macOS），透過 `dart:ffi` 載入 `libsl3` |
| `deploy/` | 節點設定範例與 systemd 服務檔 |

## 一分鐘試用（本機）

```sh
cd core
./build/sl3 demo -link-only     # 在本機開一個示範節點，印出 sl3:// 連結
```

然後打開 `app/build/macos/Build/Products/Release/sl3_client.app`，貼上連結，按連線。連線後系統或瀏覽器的 SOCKS5 代理設為 `127.0.0.1:1080` 即可。

## 上線時的建議做法

1. **帳號後台**保管簽發金鑰（issuer），用戶付費／續費時簽發短效憑證（建議幾小時到幾天），寫入方案、限速、裝置數。
2. **App** 在裝置上自己產生裝置金鑰，只把公鑰送給後台換憑證。私鑰不離開裝置，也不放進分享連結。
3. **節點**只需要兩樣東西：節點私鑰和後台的簽發公鑰。節點不存用戶資料，也不記錄目的地。
4. 節點網域放一個真實網站，`fallback` 指向它。憑證用正式 CA 簽發。
5. 每個節點用自己的節點金鑰。

## 開源前還要做的事

- 第三方密碼學審計，並對握手做形式化驗證。
- 補 uTLS 瀏覽器指紋，以及 WebSocket、HTTP/2、QUIC 傳輸層，方便走 CDN。
- 補 Android（VpnService）和 iOS（Network Extension）的整機 VPN 模式。目前客戶端殼是本機 SOCKS5 代理模式。
- 補互通測試向量，方便其他語言實作。
- 決定 GitHub 倉庫名稱與授權（目前用 Apache-2.0），由團隊決定後再推上去。
