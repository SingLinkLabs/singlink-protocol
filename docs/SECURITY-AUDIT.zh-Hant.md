# SingLink Beta 協議安全審計報告（第 1 版草案 → 第 2 版草案）

日期：2026-11-12

## 審計範圍與方式

- **範圍：** 協議設計、規格書、Go 程式碼、命令列工具、給 App 用的 C 介面，以及部署設定檔。
- **方式：** 兩組獨立審查人員各自在程式碼副本上同時進行，一組審「密碼學設計」，一組審「程式實作」。標明「已重現」的問題，都有寫測試或攻擊示範程式實際證實。
- **限制：** 這是**內部審計**，不能取代第三方審計公司的正式審計。正式對外宣稱「穩定版」之前，仍建議請第三方審計。

## 總結

| | 嚴重 | 高 | 中 | 低 | 資訊 |
|---|---|---|---|---|---|
| 密碼學設計 | 0 | 1 | 6 | 5 | 3 |
| 程式實作 | 0 | 1 | 8 | 6 | 1 |

**沒有任何問題能破解用戶流量的加密或身份驗證。**

最重要的三類問題：
1. **節點可被辨認：** 審查者能從回應時間判斷「這台是 SingLink 節點」，會被封鎖單位用來找節點。
2. **節點可被打掛：** 攻擊者大量開連線耗盡檔案控制代碼，節點程式會直接退出。
3. **可繞過內網封鎖：** 透過 NAT64 等特殊位址，用戶可以讓節點連到機房內網。

**全部「高」和「中」等級的問題，都已在第 2 版修好或緩解。**
- 每個修正都有對應的回歸測試，以問題編號命名。
- 所有解析器都加了模糊測試，累計跑了數百萬次，沒有任何崩潰。

## 修正重點（白話版）

| 編號 | 問題 | 怎麼修 |
|---|---|---|
| C-1、C-2 | 探測者送短資料或半套握手，節點要等 10 秒才轉給網站，正常網站會立刻回應，所以能被辨認 | 改成收到第一個封包就判斷，不論送什麼都立刻轉給網站，時間上看不出差別 |
| C-3 | 過期很久或被封鎖的帳號連線，節點仍會用協議回覆，等於自曝身份 | 這類連線改成默默轉給網站。只有過期 24 小時內的帳號會收到「已到期」提示，方便 App 提醒續費 |
| C-4 | 連線在中途被切斷，程式會誤以為傳送正常結束 | 只有收到「結束」標記才算正常結束，其他情況一律回報錯誤 |
| C-5 | 節點重啟後，攻擊者可以把截到的舊請求重放一次 | 節點只接受「啟動之後」產生的請求 |
| C-6 | 節點的第一個回覆長度固定，形成特徵 | 回覆合併成一個封包並隨機填充長度 |
| C-7 | 文件把抗量子能力說得比實際強 | 文件改成準確描述。新增節點金鑰輪替功能，建議每天或每週換一次 |
| C-8 | 特殊的「弱裝置金鑰」可以偽造裝置證明 | 簽發和驗證時都拒絕這類金鑰 |
| C-11 | 同一把金鑰加密太多資料，會超出安全上限 | 每加密 1600 萬次自動換一把新金鑰 |
| C-12、I-6 | 封鎖帳號後，已經連著的連線不會斷 | 封鎖後 10 秒內自動斷線。可以按帳號、按裝置或按單張憑證封鎖。憑證預設有效期從 30 天改為 1 天 |
| I-1、I-2 | 大量空連線會讓節點程式直接退出 | 連線數上限、每個 IP 的連線上限、出錯自動重試，系統服務也設定成崩潰後無限次自動重啟 |
| I-3 | 攻擊者重複送同一段垃圾資料，迫使節點每次都做耗 CPU 的解密 | 記住失敗過的資料直接跳過。不斷失敗的 IP 不再解密。同時解密數有上限 |
| I-4 | 可以繞過內網封鎖 | 封鎖清單補到完整的 IANA 特殊位址，也封鎖節點自己的 IP，系統層再加一道防火牆 |

| I-9 | 電腦上的其他程式可以搶走 UDP 連線 | UDP 只接受發起連線的那個程式 |

| I-15 | 伺服器部署設定不夠嚴格 | 系統服務加上完整沙盒，節點私鑰改由系統憑證機制保管 |

## 接受的風險（已寫進文件）

- **本機 SOCKS5 代理預設不需密碼：** 系統全局代理模式下，很多 App 不支援代理密碼，所以預設關閉。程式已支援隨機密碼，有需要可以打開。改成真正的封包層 VPN（macOS／iOS 用 Network Extension，Android 用 VpnService）之後，這個風險就不存在。
- **不經 TLS 時可被辨認：** 協議內層的資料有結構特徵，靠 TLS 外層隱藏。不建議使用純 TCP 模式對外。
- **首包內容不具前向保密：** 首包包含目的地和最前面的 8 KB 資料。只要定期輪替節點金鑰並刪除舊金鑰，就能限制影響範圍。
